# V2 M1：角色库与稳定引用

日期：2026-10-23。本次是 V2 第一模块，后续首帧控制视频、一致性审阅和修复尚未实现。

## 已交付

- 项目内角色身份、可见历史别名、独立青年／老年等造型与不可变历史版本。
- PNG / JPEG / WebP 主参考图上传、实际解码校验、10 MiB 和 4096×4096 限制、动画拒绝、受控本地图片存储。
- OpenRouter 单人候选图生成、模型与估价展示、独立费用确认、持久任务、重复请求去重、未知提交与中断保护。
- 造型版本及生图任务保留身份、风格、提示词、模型参数和内容摘要；上传来源与测试替身可区分。
- `@` 角色／造型候选、稳定 ID 绑定、图片与精确版本查看、旧引用提示、显式更新版本、影响镜头提示。
- 角色定稿绑定视觉清单；改名保留引用和确认，图片／描述／风格变化撤销确认；风格变化同步推进库版本，阻止过期页面确认未看过的内容。
- Pi 重新规划使用已登记角色 ID。确定性宿主验证引用、控制图片提交；模型不持有生成或审批能力。
- 旧库迁移前一致性备份，V1 保持可用；显式升级保留原素材并撤销旧许可。V2 视频在服务端等待 M2 开放，避免把未参考图片的文生视频冒充受控生成。
- 跨窗口修改保留本地未保存文本并提示冲突；角色写入期间禁止切换项目，异步响应按当前项目过滤。

## 开发与检查记录

- 开始前：原有 61 项测试通过。
- 数据层：15 项新增测试先失败，完成后连同原领域测试 28/28 通过。
- 图片与任务：先验证缺失模块失败；完成后 9/9 通过、累计 85 项测试通过。动画测试修正了相同帧被编码器合并的错误测试素材，改用真实双色双帧 WebP。

- 第二轮审查复现风格改变后旧页面仍可确认。新增第 5 个回归先失败，再通过推进角色库版本修复；现有合法操作测试同步改为读取当前版本。
- 最后补充默认造型变化的第 6 个回归：已绑定的裸角色名称不能随新默认项改指其他造型。失败复现后改为优先保留唯一稳定绑定，并经独立复核。
- 浏览器主流程先因缺少 V2 界面失败，完成后上传／定稿／改名／失效与测试候选图两条流程通过。
- 独立界面审查复现轮询覆盖本地编辑、旧请求串回旧项目。两个浏览器回归先失败后通过；同时补齐模型名称和引用版本展开查看。M1 浏览器用例现为 4 项。
- 后端和界面均经过独立规格审查与代码质量审查，已修复审查提出的问题。

最终累计验证及本地服务交付结果记录在 `docs/delivery.md` 的同日 M1 条目。

## 验收边界

本轮全部自动化测试使用明确注入的模型／云端替身，实际执行 SQLite、图片解码、Fastify、Pi SDK、FFmpeg 和完整 Edge 浏览器。没有提交真实付费图像或视频请求；没有将替身质量当作云端生成效果。

角色生图 HTTP 请求结构已测试，但真实端点的账号可用性与生成质量仍需用户在界面明确发起一次候选图生成后验证。真实 DeepSeek 规划的既有 V1 验证记录仍保留，不代表本次所有 V2 提示词均已实测。

未知提交不提供一键清空后重发；需要先核实供应商账单和任务。尚无自动图片理解、视频人物一致性验证、自动修复、多宫格联合生成、配音、资产市场或完整剪辑器。
