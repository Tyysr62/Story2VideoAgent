# M2：项目生产库、首帧与图生视频

用户已验收 M1，授权进入 M2；新增要求是所有生成的图片、视频与 Prompt 按项目永久保留并可导出。用户已有对象存储，将在本地配置。沿用已批准的角色确认、首帧确认与明确付费发起规则。

## 范围与选择

采用项目内不可变生产记录，不引入跨项目市场。每条记录保存输入、Prompt、模型参数、依赖、时间、状态与输出摘要；换版、失败、未被选中都保留。上传的参考图也纳入项目库，方便完整归档。保存分镜时归档每版结构化结果及其图像／视频 Prompt；每次付费请求前归档实际编译输入。旧数据只回收数据库中仍存在的内容，原先未记录的历史 Prompt 标为缺失，不用当前 Prompt 冒充。

项目界面显示生产库，按图片／视频／Prompt 过滤，可预览、下载单项及导出整个项目 ZIP。ZIP 含 manifest.json、文本与结构化输入、所有已保存媒体及缺失／失败状态。文件使用稳定 ID 命名，中文项目名作为下载名；不导出环境文件、数据库、诊断日志、密钥和签名 URL。导出采用流式 ZIP，不将整部视频装入内存。

M2 首帧输入由角色所选版本、按顺序排列的参考图、画风、构图与镜头 Prompt 编译。Qwen 端点验证通过后才提交；参考数量超限直接阻断。每次重做建立新记录，当前选择单独保存。首帧指纹依赖实际图像输入；仅改变无关镜头可复用未变内容。

全部当前首帧与视频输入在同一清单确认，再由用户发起图生视频。确认绑定首帧摘要、分镜、引用与模型配置。视频以已确认首帧作为 first_frame；不把本机 URL 或人物肖像当作镜头首帧。选定单镜头可先试跑，所有有效片段齐备后本地拼接。

图像参考通过 Base64 data URL 直传。视频使用用户自有 S3 兼容对象存储：服务端上传已确认首帧，生成限时签名 HTTPS GET URL，提供给 OpenRouter。未配置时在付费前阻断。不会开放本机文件、自动上传至第三方图床，或将签名 URL 纳入导出。存储与推理凭据只保存在 .env.local。

失败／未知分开：付费请求前保存任务；视频任务 ID 及时落库，恢复只轮询原 ID；无 ID 的中断标 unknown，禁止自动重提。产物文件按记录 ID 唯一命名并校验摘要；旧记录与文件不覆盖。

## 串行交付

1. 生产记录与历史回收：SQLite 增量迁移、分镜版本／Prompt、角色图与 V1 产物归档。
2. 项目生产库 API、单项下载、流式 ZIP 及界面；项目隔离、路径校验与完整导出测试。
3. 首帧编译／生成／选择、费用估算、局部重做与整组确认；真实请求契约替身测试。
4. 私有对象存储传输、图生视频、持久任务恢复、依赖复用与合成；API、浏览器和累计回归。

每步测试通过并提交后再进入下一步。最后联调；真实付费验收与离线测试分开，不自动消耗模型额度。大版本验收后询问是否推送 GitHub。M3 自动视觉审计与修复不在 M2 实施。

接口依据：[OpenRouter 图像参考](https://openrouter.ai/docs/guides/overview/multimodal/image-generation)、[视频首帧](https://openrouter.ai/docs/cookbook/video-generation/image-to-video)。当前目录默认 Qwen Image 2.1 Turbo / 1K 与 HeyGen Video 1 / 480p，实施时查询具体端点能力与参考计费。
