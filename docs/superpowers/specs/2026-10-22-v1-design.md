# Story Agent V1 specification

用户已确认 V1 / 第一阶段交付，并要求逐模块测试通过后再进入下一模块，全部完成后联调。

## Scope

- DeepSeek through the real Pi Coding Agent SDK plans a variable number of shots. The only shot-count constraint is 1–20; no forced 3/6-shot template and no silent truncation.
- A structured storyboard contains title, visual style, characters, and ordered shots with scene/action, camera, image/video prompts, character references and positive duration.
- Human editing/approval binds an exact project revision. Mutation invalidates approval; stale requests return conflict.
- Updated requirement: all generation models use cloud APIs, with OpenRouter selected by the user. Default image is FLUX 3 Image Klein (768); default video is H3 Max (480p, silent). FFmpeg local composition is explicitly permitted. Scripted planning and color-card media are confined to demo/tests and visibly marked.
- Local single-user app on loopback. SQLite stores projects, jobs, artifacts and event history; artifacts are permanent local files. Agent conversations are separate.
- Durable executor resumes saved cloud task IDs after restart, preserves completed artifacts and stops uncertain submissions to avoid duplicate billing. Unique revision/kind/shot keys prevent duplicate artifacts. Editing while generation is active is rejected in this V1; cross-version reuse is deferred.
- A React/Vite UI provides story input, AI planning, editable shot cards, approval, price estimate, progress, clip previews and final playback/download. No public deployment or accounts. Paid calls require explicit current-version approval and generation submission.
- A missing DeepSeek key produces an explicit configuration error, never a heuristic pretending to be AI. Tests use an explicitly injected scripted Pi model. Real-provider smoke is separate from offline acceptance.

## Modules and ownership

1. Domain + SQLite repository: src/domain, src/storage; tests/domain-store.test.ts.
2. Pi / DeepSeek director: src/director; tests/director.test.ts (real SDK, scripted streaming model, no network).
3. FFmpeg composition: src/media; tests/media.test.ts (real decoding/concatenation). M3b adds OpenRouter cloud contracts in tests/openrouter.test.ts as a separate passing gate before M4.
4. Durable workflow: src/workflow; tests/workflow.test.ts (approval, deduplication, failure, restart).
5. HTTP API + React interface: src/server, src/client; tests/api.test.ts (validation, secrets, media isolation).
6. Integration: tests/integration.test.ts and tests/e2e; real browser, SQLite, Pi HTTP transport against a local model fixture, FFmpeg, cloud response fixtures and database close/reopen recovery.

Each module follows red → green → cumulative regression. Actual results are recorded in docs/delivery.md. Use a local pinned Node runtime because the machine global Node 22.16 is below Pi's >=22.19 requirement. No modifications to global Node.

## Validation boundaries

Cloud model live evaluation requires a key in the ignored .env.local. Provider credentials remain server-only. Prompt input is untrusted; SDK only has the storyboard proposal tool and no filesystem/shell/project extension discovery. Server errors must not echo secrets or provider response bodies.

Artifacts can only be served through database-known IDs under the configured data root. API bodies and model turns have limits. External model output is schema checked and bounded to 20 shots before persistence.
