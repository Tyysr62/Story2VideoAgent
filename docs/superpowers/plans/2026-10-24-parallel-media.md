# 媒体并行生产实施计划

**目标：** 按用户“能并行的地方就并行”的要求，消除首帧与视频逐镜头等待，保留成本确认、产物归档及任务恢复。

**设计：** 全应用共享图片和视频两个独立 FIFO 并发队列，默认各 3，环境变量可设 1–8。角色图片、V1 和 M2 共用同一服务商并发预算；同一项目角色库版本修改与人工确认仍保持依赖顺序。队列只改变执行顺序，不改变生成参数或缓存摘要。失败停止该批未开始任务，等待已开始任务落库后才解除项目忙状态；不自动重提收费请求。M2 完成时重新读取最新状态再写入，避免并发覆盖其他镜头；合成按分镜原顺序。

**取舍：** 无界并行容易触发限流；单纯 Promise.all 会在首个拒绝时过早解除忙状态。采用有界、等待全部在途任务收尾的队列。供应商内部排队时间无法由本地并发保证消除。

**技术栈：** TypeScript、现有 SQLite/FFmpeg、Vitest、Playwright，无新增依赖。
