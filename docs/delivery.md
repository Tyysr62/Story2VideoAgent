## Integration findings and repairs

- The first real browser run failed when the workflow stored a mock image as `.image`. The original media test only exercised `.png`. The test was changed to `.image`, failed with the same FFmpeg error, then passed after explicitly selecting PNG/image2 output. Cloud media saves response bytes and is independent of the mock encoder.
- Independent code review reproduced planning/generation overlap: an approved old storyboard could generate while a new plan was pending, allowing a new revision to inherit the wrong final artifact. Replanning now revokes approval; generation rejects planning before and after async validation; failure/final transitions check ownership by revision/status. Two race regressions were observed red, then green.
- Review reproduced paid image results being resubmitted after local storage or metadata failures. Successful responses followed by local failures now become `unknown`, blocking another automatic POST. Local-write, missing-artifact and metadata-failure regressions were observed red, then green.
- Review reproduced existing video IDs being blocked after three polling attempts. Existing-ID query/download resumes now bypass the no-ID attempt limit. The restart integration test reopens SQLite with five previous attempts and completes without a new POST.
- Review also reproduced failure to persist an accepted video ID being treated as safely retryable. ID-write failure and null success-response tests now produce `unknown`. Both prevent a second paid submission through the workflow's unknown-state gate.
- Initial Chromium test launch occurred before its browser download finished. After installation, a separate media diagnostic confirmed headless-shell has no H.264 decoder (`canPlayType(avc1)` empty and `DEMUXER_ERROR_NO_SUPPORTED_STREAMS`), while Edge supports it. Browser acceptance now uses full Edge on Windows and full Chrome on Linux/macOS/CI. The final gate passed actual video playback, with currentTime advancing; no codec-related assertion was skipped. The CI workflow is provided but has not been executed remotely.
