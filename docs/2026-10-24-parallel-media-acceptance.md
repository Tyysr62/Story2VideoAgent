# 首帧与视频并行生产验收

## 改动与依赖

原 M2 按镜头逐一 await 首帧、逐一 await 视频；每个视频从上传到轮询完成再下载落库，之后才进入下一个镜头。现使用全应用共享的 FIFO 图片和视频队列，默认各 3 个槽位；两类队列独立。`IMAGE_CONCURRENCY` / `VIDEO_CONCURRENCY` 可配置为 1–8，非法值阻止启动，设为 1 即串行。

M2 首帧与视频、V1 图片与视频都接入队列。不同项目和角色候选图共享对应配额，防止按项目放大并发。V1 图片齐备后批量视频生成；M2 仍保留角色定稿、首帧审阅确认、费用确认等有依赖的阶段。所有视频齐备后按原分镜顺序合成一次。

失败首先同步停止该批排队项，再记录诊断与保留输出；已进入执行的任务仍会收尾归档，全部结束后解除项目忙状态。不取消或自动重复提交收费请求，已保存 providerTaskId 仍恢复查询原任务。并行完成时重新读取最新 M2State 合并，避免旧快照覆盖别的镜头选择。并发配置不进入模型参数与缓存指纹，不导致素材或首帧确认失效。

## 证据与复核

新增队列、M2 与 V1 测试先复现串行只能启动一个请求，再验证同时三个执行、自动补位、跨批共享上限、乱序完成不丢结果、合成原顺序、失败停止排队及 drain、云任务恢复与本地目录失败归档。针对性测试 32 项通过。

独立复核发现失败文件归档期间可能补入下一项请求的问题，已通过同步 stop() 修复；复核确认没有剩余阻塞问题。新增测试在失败清理人为暂停、其他在途任务完成时确认后续任务不会启动。旧测试不再假定第一个完成或失败的是第一镜头，改按任务 ID 核验重试与产物复用。

仅用本地等待替身测量调度开销：6 个各等待 150 ms 的任务，串行 948 ms，并发 3 为 315 ms，观测峰值分别为 1、3。该测量没有网络或模型请求，不能推断真实云端一定获得相同比例提速。没有为验收调用付费生成接口。

并行版本 `npm run verify` 通过：类型检查、22 个测试文件共 178 项测试、生产构建，以及 12 项浏览器端到端测试。独立复核的 32 项针对性测试通过；本地目录失败与同步停排队均有回归覆盖。

## 已占用端口的启动保护

部署等待期间，操作失误在旧服务仍生成时启动了第二实例；旧入口在 listen 之前执行恢复，导致在途项目被误标中断。原进程仍继续生成。已通过精确匹配恢复错误、事务更新的本地脚本恢复该项目忙状态并清除成功产物的残留中断错误，未修改故事、素材、Prompt 或云任务 ID；旧批次继续正常完成镜头。

入口现在在打开数据库之前检查目标端口，已占用时直接退出，不执行任务恢复。新增进程级回归：占用端口并放置哨兵数据库文件，子进程必须报 EADDRINUSE 且不打开该数据库；旧代码先复现 SQLite 错误，新代码通过。独立复核通过。该检查针对端口已经被占用的重复启动，不是多进程数据库锁。

加入启动保护后的最终 `npm run verify` 全部通过：类型检查、23 个文件共 179 项自动化测试、生产构建与 12 项浏览器联调。
