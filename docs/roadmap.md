# 更新路线图

更新日期：2026-10-24。本文区分已交付与后续计划；后续模块尚未实现，不代表效果已经验证。

## 当前：M2.2 已交付

- AI 自主规划 1–20 个镜头，支持编辑、版本确认与角色稳定引用。
- 项目角色库、年龄/服装造型、上传及参考图片生成，Qwen 默认 2K。
- 项目生产库保存历史图片、视频、分镜、Prompt 和参数，支持 ZIP 导出。
- 角色参考首帧、整组审阅、OSS/S3 素材传输、HeyGen 图生视频与 FFmpeg 成片。
- 首帧和视频各默认 3 并发，跨项目共享上限；保存云任务 ID、保留未知提交和失败输出。
- 环境声、音效、对白、旁白共同编辑，增加自然台词和表演规划。当前仍依赖模型原生音轨，未保证固定声线、逐字发音和真实混音质量。
- 最近完整验收：183 项自动化测试、15 项浏览器测试；链路测试采用云端替身，真实生成质量需另行评估。

## 下一阶段：M3 检查与局部修复

沿用既定 V2 设计，按以下子模块依次交付，每个子模块测试通过后再继续。

| 顺序 | 交付内容 | 验收标准 |
| --- | --- | --- |
| M3.1 参考图与首帧检查 | 用 DeepSeek 官方图片理解检查角色身份/年龄、服装、人数、关键道具、场景与构图；角色图片描述只给建议，不覆盖用户原设定 | 返回 `pass / fail / uncertain`、问题类别和对应资产证据；工具失败或证据不足不得算通过；结果、模型和请求归档 |
| M3.2 视频与声音检查 | FFmpeg 抽取首/中/尾帧，检查漂移、时代/场景衔接和剧情要求；声音先检查音轨、静音占比与响度 | 抽帧证据可定位到镜头与时间点；静音/有声预期分开；视觉检查不宣称验证发音或台词内容 |
| M3.3 定向修复 | Agent 根据证据提出改首帧、动作 Prompt 或声音计划的方案，用户选择镜头并确认费用后执行，再检查 | 每次操作每镜头最多一次付费生成；设置费用/次数边界；旧版可对比，未改镜头复用；首帧变化后重新确认，下游视频按依赖失效 |
| M3.4 联调与效果评测 | 固定故事与人工标注，对照纯文生视频、文字角色、角色参考首帧、检查+局部修复 | 记录人物/造型正确率、剧情符合程度、修复次数、时延、Token 和实际费用；保留失败例和原始证据，不预设提升幅度 |

目标闭环：检查证据 → 修复建议 → 用户确认 → 单镜头执行 → 再检查 → 合成。首版付费修复保留人工确认，不自动无限重试。

检查图片与抽帧沿用 DeepSeek API；生成沿用 OpenRouter，图片处理与合成允许本地 FFmpeg。若要核对实际说出的台词，需后续接入 ASR API，并区分识别不确定与台词错误；固定声线需要另评估独立云端 TTS，不作为视觉修复闭环的前置条件。

## 后续建议：执行控制与开源交付

完成 M3 后，再完善队列进度、单镜头耗时/费用、暂停后续提交、原云任务恢复及 unknown 的人工核实/绑定入口。已提交任务是否能云端取消，实施时再核实供应商接口；本地停止排队不等于取消云端费用。

开源展示补充可复现演示、架构与实际执行轨迹、少量人工标注故事、对照实验和已知失败场景。优先展示有证据的 Agent 决策与局部修复收益。多用户权限、复杂剪辑器、资产市场和模型训练不进入下一阶段。

## 交付约定

每个模块：行为测试 → 实现 → 回归与浏览器联调 → 交付说明。全部子模块完成后再跑完整闭环联调。真实付费质量验收与离线工程测试分开；大版本完成后先汇报，再询问是否推送 GitHub。
