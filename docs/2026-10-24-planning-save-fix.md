## 已验证的缺陷

`validateStoryboard` 允许带括号的角色名称，而 V2 角色库 `adoptPlan` 采用限制 @ 引用分隔符的 `characterInputSchema`。例如模型返回 `陈伯（老年）` 时，Pi 原先接受分镜，随后角色入库抛出 `ZodError`，Workflow 将其替换为通用失败。此场景已用离线测试复现，与用户看到的错误相同；失败时数据库事务会回滚。

修复将角色库名称规则共享到 V2 Pi 工具参数及接收校验，并在 Prompt 中说明年龄、服装写入描述，名称不用空格或括号；首次规划没有造型版本 ID 时省略 `characterRefs`，由应用绑定。真实 Pi SDK 离线测试验证工具拒绝非法名称后，模型可根据反馈提交修正方案。V1 名称规则保持兼容。

Workflow 在角色入库前归档实际返回的分镜，成功或失败均标注对应状态；角色名称校验失败给出固定中文说明，不输出未经处理的异常、供应商返回或凭据。未知异常仍使用安全通用错误。新的归档记录不等于已确认分镜。
